# KiCad Round Tracks
A native arc-based track rounding plugin for KiCad.

The goal is to algorithmically melt a PCB design, smoothing all tracks in a predictable manner. 

![example](https://mitxela.com/img/uploads/sw/kicad/example.png)

For best results, use in conjunction with this [teardrop plugin](https://github.com/NilujePerchut/kicad_scripts).

I have written extensively about my kicad melting experiments [here](https://mitxela.com/projects/melting_kicad) and [here](https://mitxela.com/projects/melting_kicad_2).

## About this fork
This is [jrowe88](https://github.com/jrowe88)'s fork of [mitxela/kicad-round-tracks](https://github.com/mitxela/kicad-round-tracks). It replaces the rounding engine with one that plans every fillet first and then commits them all at once: it cleans up hidden fragments before corners, shares short segments fairly between neighbouring corners, merges close same-direction bends into one arc, keeps arcs clear of other nets, and marks the corners it had to leave sharp. The subdivision mode and the *Passes* setting are gone; all curves are KiCad's native arcs. Everything else here is mitxela's work and that of the earlier authors listed under History.

## Use

__For the KiCad 5 compatible version, please use the kicad-5 branch.__

The intended use is to have a source PCB file, which is easy to edit, and a rendered output file, generated by this plugin. After running DRC on the output, you can then go back and adjust the original file before running the plugin again.

If you select part of the board, only the selected tracks will get melted. If nothing is selected, the whole file will be processed.

"Create a new file" does not immediately write anything to disk, it merely appends "-rounded" to the filename so that the next time you hit Save it won't overwrite the original.

The rounded sections are KiCad's native PCB arcs. These _can_ be adjusted after the script has run, but I still recommend keeping the unrounded source PCB file. Each run is a single undo step, so Ctrl+Z puts everything back exactly.

### Radius

"Radius" is the true arc radius on a 90° bend. Shallower bends get a larger arc for the same setting, so they look as gentle as the 90° ones: a 45° bend gets about 2.7× the radius. A smaller arc is used when the tracks are too short or something is in the way. Corners on a pad, a via or an existing arc are skipped, so track ends there never move. Where other copper of the same net joins a track partway along (another track's end, an arc, a via or a pad), the arc stops at that point, so the joint stays on copper; if that leaves too little room, the corner stays sharp. A radius of 0 turns rounding off for that netclass, like unticking it.

When two corners share a segment too short for both, the segment is split between them in proportion to what each one asked for. Two or more bends that turn the same way and are joined by short segments (two 45° bends close together, say) are replaced by one larger arc, if it fits; this is what you'd do by hand. Bends that turn opposite ways (an S-jog) are never merged, and neither are bends with same-net copper joining the short segment between them.

Before rounding, collinear fragments and tiny slivers just before a corner are merged away, so a hidden scrap of track doesn't shrink the curve.

"Min radius" is a floor. A corner that can only fit an arc below it is left sharp rather than given a tiny curve (so a netclass radius below Min radius leaves every corner in that class sharp, each with a warning). Every arc is tangent to the tracks on both sides; if that's not possible, the corner stays sharp.

### Junctions

Where three or more tracks meet, each pair of neighbouring tracks gets an arc, and every track is shortened by the same amount so the arcs meet them cleanly. A junction is all or nothing: if any of its arcs can't fit, the whole junction stays sharp. Tick "ignore junctions" to leave them all alone. Junctions never take part in merging.

### Clearance

Each new arc is checked against other nets' tracks, arcs, vias and pads (through-hole pads on every copper layer), drilled holes, the board edge, and keepout areas that forbid tracks, using the netclass and board clearances. If an arc doesn't clear, it is shrunk until it does; if it still doesn't clear at the min radius, the corner stays sharp. Custom rules in a `.kicad_dru` file and copper text are not modelled, and zone fills are ignored (refill them afterwards), so always run DRC after rounding.

### Warnings

Every corner left sharp because it was too short or blocked gets an arrow and a short reason ("too short" or "clearance") on the User.Comments layer. Corners skipped on purpose (where the track width changes, and junctions when "ignore junctions" is ticked) get no arrow; the summary counts them as skipped. All of them are in one group named `round-tracks-warnings`, so you can select and delete them in one click. Each run removes the previous run's group first; if you rename or ungroup it, the old arrows won't be removed automatically. When it's done, the plugin tells you how many corners were rounded at full radius, reduced, merged, left sharp and skipped.

### Unround

"Unround" turns arcs back into corners where their tangents meet. It is approximate: a merged arc comes back as a single corner, and cleaned-up fragments don't come back at all. Arcs that turn nearly 180° (hairpins) are left in place, and the plugin tells you how many. Ctrl+Z straight after a run is the exact undo.

## Installation
Now available from the Plugin and Content manager.

For manual install, clone or unzip this repository in a KiCad plugin folder. You can list the exact paths where KiCad will search for plugins by opening the scripting console in pcbnew and running:
```
import pcbnew
print(pcbnew.GetWizardsSearchPaths())
```

Under Preferences / Preferences / PCB Editor / Action Plugins, you can choose whether to have a button on the toolbar for quick access to the plugin.

## Tests
The tests run with KiCad's bundled Python and need `kicad-cli` (installed with KiCad) for the DRC checks. From the repository root, on Windows:
```
"C:\Program Files\KiCad\10.0\bin\python.exe" -m unittest discover -s tests -t . -v
```
A full run takes a few minutes. `tests/test_geom.py` covers the pure geometry; `tests/test_cases.py` builds a small board for each problem case, rounds it headless and runs DRC on the result. Temporary boards are written outside the repository.
